# 迈从 G7 / V9 Pro（v1.1.1）

此包包含此前设备适配及六种图标样式，版本保持1.1.1。当前电脑未连接目标设备，本轮无G7或V9 Pro实机验证。

## G7电量

仅接受3837:1014/1018的无线候选或A8A4:2255直接USB，且原始产品名完整等于MCHOSE G7或MCHOSE G7 Pro（忽略大小写及首尾空白）。不按3837品牌或公共2255编号直接命名G7；G7 MAX、K5 Ultra等不套此路径。

每个物理USB父实例只允许一个FF01/0010专用集合，输入/输出同为65且Feature为0（2026-11-06官方来源复核后收紧）。重复同一路径去重，不同候选路径不猜测；打开后再次核对VID/PID、产品名和实际集合。

电量协议依据官方gmouse-610实现的getBatteryInfo请求：5530A50B2E0101010000，前置报告编号0，组成65字节请求；响应必须为0+AA30，不在任意偏移搜索标记。官方来源仅支持当前原生65字节路径，64字节纯解析器作为历史研究保留，不用于打开设备。报告能力表存在时必须成功取得唯一输入/输出编号0；常量报告没有能力项时仍须符合精确集合和65字节布局，待真实固件反馈核实。

每次先排空旧输入再发电量读取，至少两次完整有效新响应才采用第二次值。百分比0–100、充电0/1；拒绝请求回显、错位、截短、越界、第二次缺失和未排空的旧队列。每次响应窗口1秒，原生工作线程外部等待上限3.5秒；线程保留句柄与原生I/O资源至操作真正结束，迟到结果不被下轮采用。

原始名称与描述符确认型号分别保存。无线候选可确认接收器；本协议没有独立RF在线字段，两次接收器响应也不据此把PeripheralConfirmed设为true。安全模式、停用识别、集合缺失均不查询。不使用旧通用迈从/形状兜底，导出报告不绕过实例边界再发通用探针。

真实设备若不符合这些布局，显示未知并导出新报告补证；不承诺全部G7固件均已验证。

## V9 Pro音频

按用户本轮明确选择，V9 Pro保持**仅名称、播放音量和可恢复的麦克风静音**，不启用HID电量读取。291D:385D与S9/G9共用，不能据此给别人的设备命名。

系统音频页保留Windows原始端点名称。补充识别Windows把V9 Pro输出列为扬声器类型、名称为“MCHOSE V9 PRO”或“扬声器 (MCHOSE V9 PRO)”的情况。名称需完整模型边界，S9或V9 PRO MAX不会由该规则变成V9 Pro。现有Windows Headphones/Headset类型规则保持原样。

控制绑定实际音频端点ID，断开时不自动改控默认设备。麦克风沿用已有保守物理容器关联规则；Windows只报扬声器类型、关联证据不足时，在音频页手动选择麦克风。静音可恢复，不禁用驱动或更改系统隐私权限。打开页面、刷新和切换选择本身不写音量/静音。

## 使用及验证

退出旧程序后解压本包。G7接收器连接、鼠标唤醒、识别开启且安全模式关闭后刷新；若仍无电量，导出新报告查看“G7专用”或“G7边界”。V9 Pro从设置/托盘的耳机音频页选择Windows输出端点，调整音量或选择对应麦克风静音。
