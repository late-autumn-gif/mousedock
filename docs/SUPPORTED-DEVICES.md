- **识别**：设备能出现在面板上并且名称正确
- **电量**：能读出真实百分比（`—` 表示当前未取得有效读数，不等同于硬件不支持）

### 为什么经典蓝牙耳机没有电量

1.3.1 开始会先查询 Windows 的 `System.Devices.BatteryLife` 与独立充电属性，按蓝牙地址关联端点和 PnP 容器。Windows 已提供有效百分比时可以直接显示；下列历史实测只适用于当时测试的耳机，不能推断所有经典蓝牙耳机都不支持电量。未提供系统属性且无有效协议回包时继续显示 `—`。

实测三条路都不通：

1. Windows 设备属性里没有 `BatteryLevel`
2. 耳机没有 BLE 节点，GATT 不存在
3. HFP 的 `+IPHONEACCEV`：抢占通道后用 AG 身份握手，耳机连 `+XAPL` 都不回 —— 固件不支持

能读到的只有走厂商 App 的私有 RFCOMM 服务（`fe010000-…`），需要该 App 的协议。

## 有线

`4C4A:4155` 竹林鸟玄武（ZhuAudio ZG2）从 1.3.3 起支持 USB HID 设备识别。Windows 的音频设备与 Consumer Control HID 已在本机核对；连接类型显示 USB。设备识别不代表电量协议已适配，当前电量保持未知。

| 情况 | 识别 | 电量 |
|---|---|---|
| USB 有线键鼠 | ✅ 通道显示「有线」 | — 标准 HID 无电量上报 |

有线设备若厂商在私有 HID 集合里提供电量，可以按厂商协议接入（同 AULA 的方式）。
