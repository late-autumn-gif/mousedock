# MouseDock 电量诊断报告 v2

## 抓取方式

1. 让设备保持故障发生时的连接方式。测试 2.4G 时，确认外设仍在 2.4G 档并唤醒外设。测试插线后读数时，勾选「正在测试插线后的电量」。这项标注来自操作人，独立于协议中的充电标志。
2. 在「导出错误报告」里选对应设备。如果设备没有出现在列表，选「全部设备」。
3. 保存 ZIP。应用在后台做三轮 HID 采样，每轮结束后等 8 秒再开始下一轮，实际总耗时还取决于设备响应。适配时可一并提供商品完整型号、固件版本和对应时刻官方驱动的读数。

单设备按物理实例在接口查询之前限域。同一 VID/PID 的另一只接收器不会因型号相同被加入。全部设备模式使用同一格式，保留没有适配的接口、打不开的接口及排除原因。主动查询沿用正常读取器和安全模式，不为未知设备遍历私有命令。诊断不采集 DPI。蓝牙和其他非 HID 来源在 v2 只保留应用界面快照。

## ZIP 内容

- `summary.txt` 汇总采样时间、来源、连接方式、识别状态、百分比、充电状态和失败阶段。
- `report.json` 保存 v2 清单、采样前界面快照、报告内的实例别名、轮次索引和样本趋势。连续返回 100% 标记为 `repeated-100-unverified`。
- `battery-replay.json`、`samples/02.json`、`samples/03.json` 各对应一轮。记录 VID/PID、USB 设备版本字段、MI/COL、Usage Page/Usage、HID 报告长度和可提取的报告编号、路由与查询边界、打开错误及读取结果。USB 设备版本字段不等同于厂商固件版本，报告编号为空表示能力表未给出可用编号。
- 支持帧证据的读取器记录时间、请求、响应长度和校验结果。响应仅保留解析所需字段，其他字节被遮蔽。没有帧证据的读取器仍可能提供采样时的读数或失败结果。

ZIP 保存在用户所选位置。实例编号仅在报告内有效。报告保留产品名和故障数据供预览，省略原始 HID 路径、设备实例 ID、蓝牙地址、按键输入、全局设置与缓存文件。

## 两个实机例子

| 设备 | 需要的证据 | 实机观察 |
| --- | --- | --- |
| 狼蛛 SC580 | 同一物理实例的 `089D:062F`，`FF02/0000`，33 字节 Input/Output，report 0，Identify 中 `M137`、在线、电量和充电字段。连续两次同型号在线应答后采用结果。 | 未就绪时接收器仍在，回包被识别为休眠，电量留空。唤醒并插线后连续三轮报 100% 和充电中。 |
| VGN Neon 75 Air | `391D:2A05`，`FFFF/0002`，65 字节 Feature，report 0，F7 请求和两次有效响应。校验就绪位、百分比和独立充电位。 | 插线前曾报 86% 至 87%。插线后连续三轮报 100%，2.4G 回包充电位仍为 0。 |

这些读数反映协议字段。要验证充电中的真实百分比，需在同一实例上对照插线前、刚插线、充电一段时间和拔线后的读数，最好同步记录厂商驱动的百分比及连接方式。如果插线立刻跳到 100% 且保持恒定，这批数据不足以确认实时电量或充满。

## 离线重放

```powershell
Start-Process -FilePath '.\MouseDock.exe' -Wait -ArgumentList '--replay-report ".\报告.zip" ".\重放结果.json"'
```

支持完整 ZIP 和单轮 JSON。ZIP 会重放其中所有标准轮次，旧版单轮文件仍可读取。重放只读文件，不访问硬件。当前支持 SC580、SC630 Pro、Neon 75 Air、IN9、IN9 Pro，以及通过 Omni 接收器连接的 ROG 游侠2 RX 98 无线版。结果中的 `captured` 仅表示已用解析器复核采样值，无法独立确认固件报告值与实际电池状态一致。
