# 竹林鸟烛龙 ZG4

## 设备和协议

官方网页驱动用 `3654:5055` 枚举候选 HID，按内部型号编号区分产品。ZG4 的 MID 是十进制 4101（`0x1005`）。MouseDock 同时要求完整 USB 产品串 `ZhuAudio ZG4`，并在同一物理实例内匹配厂商 HID 接口。报告 ID 取自描述符。只支持输入和输出报告长度为 64 或 65 字节的集合。

读取顺序如下。

1. 接收器命令 `0x02` 检查耳机在线。
2. 接收器命令 `0x06` 读取型号。两个接收器回复都验证 CRC，型号回复的载荷偏移 2 为小端 MID。
3. 耳机属性读取 `0xFE 0x07`。响应须匹配 Report ID、序号、帧长度和属性。属性数据至少 3 字节。首字节低 7 位是电量，高位是充电标志。电量限于 0–100。

安全模式与单设备识别偏好照常生效。缺少有效回复时不产生新读数。仅凭 USB 枚举将设备显示为 USB，确认接收器链路并取得有效电量后显示为 2.4G。

## 证据与限制

协议依据为[官方网页驱动脚本](https://drive.zhuaudio.cn/web/main.dart.js)。静态核对定位到 WebHID 过滤表、接收器响应分派、耳机属性响应分派和电量字段解码。离线测试的报文是根据这些规则构造的样本。

2026-11-12 的 1.1.7 实机诊断在同一物理实例枚举到 5 个集合。三轮专用读取均为 `NoValidValue`，报告未记录应答或失败阶段。结合官方网页驱动优先探测输出报告 `CD` 的顺序，MouseDock 优先尝试报告中的 `MI_04/COL_03`（输入 `CE`、输出 `CD`，64/64），在线应答窗口从 400 毫秒调整为 1500 毫秒。其它符合原读取器条件的同实例集合仍可尝试，报告 ID 继续从描述符获取。

新版诊断按接口区分打开、初始化、报告 ID、队列清理，以及在线、型号和电量三个查询阶段。查询可分别报告发送失败、无应答或收到但未通过验证。导出报告使用接口编号和阶段状态，无原始路径或 HID 负载。回放保留失败阶段，无报文可供重新解析时电量仍为未知。

已取得实机集合描述符，合成样本覆盖 `CD` 输出与 `CE` 输入以及正常显示链路。有效实机应答、接收器固件变体和有线模式的私有电量读取仍待验证。蓝牙沿用 Windows 系统属性和 BLE 电池服务。
