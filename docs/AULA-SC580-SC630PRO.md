# 狼蛛 SC580 / SC630 Pro 适配（v1.1.1）

本包在 X23SE 与耳机控制版本基础上增加狼蛛专用读取路径，版本仍为 1.1.1。SC580 已在本机通过本轮实际扫描；SC630 Pro 已接入官方协议，但没有本轮实机响应，不能宣称所有电脑都能读取。

SC580 旧实现按输出长度选通道，失败后尝试握手、DPI 和被动推送；新路径只发送 `00 30 00 01` 补零至33字节的 Identify 查询。每次先排空旧输入，过滤回显/无关帧，最多三次有限事务，至少两次有效同型号在线应答才采用第二次电量。休眠/未就绪可有限重试；online=0 中的旧百分比不作为新的读数。识别失败保持原始产品名，不从历史型号缓存重新确认 SC580。

SC630 Pro 原来有解析代码，但未进入新版白名单。本次使用独立且有超时上限的工作线程，仅做官方电量 SetFeature/GetFeature 事务，至少两次有效响应。请求为 report6、命令81、非零序号、长度3；每次 SetFeature 后等待130ms再读41字节 Feature。拒绝请求回显、错误长度/命令/非零序号、离线状态和越界百分比。兼容官方读取器不要求序号回显的行为，允许响应序号0并在诊断标明；这条兼容规则还需真实固件验证。

## 常量报告与编号边界

本轮 SC580 实测的值能力/按钮能力数量均为0，厂商常量报告不会生成这些能力项。不能因此把合法集合一概拦掉，也不能把空表理解成“枚举到了报告编号”。

两款的固定编号分别有历史实测/官方传输函数证据，仅在各自精确集合规则通过后使用。若能力表包含报告项，则必须成功读取并且只有一个编号，与已知编号一致；不匹配就不查询。X23SE 等其他协议仍按自己的规则处理，不套用本例。

## 实例与状态

- 先按 USB 物理父实例归并接口，每个实例只允许一个精确电量集合；重复枚举同一路径去重，多个不同候选路径不猜测。
- 打开句柄后复核 VID/PID、实际产品名和集合；不同接收器不能串用电量。SC630 完整名称优先于公共 ID 的其他协议，不走其他厂商兜底。
- 安全模式、停用识别、缺失实例/集合和超时均不发额外兜底命令。SC580 身份与电量查询不执行0x12订阅、0x13 DPI或配对、固件、灯效操作。
- 原始名称、确认型号、接收器发现、外设在线、电量有效独立保存。SC630 的 USB 连接方式暂不猜成2.4G；只看到完整型号/集合不证明它是无线接收器。
- 两款的失败扫描返回未知；应用原有缓存展示仍可能保留上一轮电量并标记 stale，这不属于新的设备响应，充电动画不沿用缓存。
- 导出报告使用本次扫描的专用诊断，不对同 VID/PID 的全部设备再发通用探针。日志含集合、报告编号来源、有效/拒绝响应及失败阶段。

## 使用与反馈

退出旧版，解压测试包，连接接收器并唤醒鼠标后刷新。保持该实例识别开启、安全模式关闭。SC580 应在 M137 身份响应通过后显示型号；SC630 Pro 若原始产品名不同，本次不会按外观/型号简称强行套协议。

若某台电脑仍失败，导出该设备的新报告，检查 hid-devices.txt 的“狼蛛路线”或“狼蛛边界”行：精确集合数量、报告能力、打开/发送失败、Identify 未就绪、Feature 无效响应等会分开记录。SC630 Pro 下一步需要这份实机报告，才能判断是名称/接口差异还是报文兼容问题。

开发验证：`dotnet run --project tests/MouseDock.ProtocolTests -c Release` 为离线回归；`--inspect-aula-battery` 为显式实际扫描，会按生产策略查询本机设备，输出只筛选狼蛛结果。默认离线测试不会访问硬件。

本轮完整离线回归10282条、设备管理45项、模拟耳机控制17项均通过。SC580 后续实际休眠扫描也返回三次未就绪，专用路径输出 Sleep、未知电量、外设未确认，未将之前82%当成新电量。本轮没有插拔充电线验证充电状态切换，也没有 SC630 Pro 实机。
