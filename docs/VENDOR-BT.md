# 第三类耳机：厂商私有协议怎么接

有些耳机的电量只在自己的手机 App 里显示，Windows 和标准蓝牙接口都拿不到。
它们通常把电量放在一个**厂商私有 RFCOMM 服务**里，这个服务的 UUID 常见是：

```
fe010000-1234-5678-abcd-00805f9b34fb
```

MouseDock 已经能连上这条通道，但**帧格式是各家芯片方案私有的**（BES / 杰理 / 络达 / 高通），
没有厂商 App 的抓包就无法凭空猜出来 —— 所以默认不显示电量，也不编数字。

## 已经做好的部分

| 能力 | 状态 |
|---|---|
| 连接厂商服务 | ✅ `Services/Detection/VendorBt.cs` |
| 探测模式（打印设备所有响应） | ✅ `MouseDock.exe --vendorbt "耳机名"` |
| 配置化读取（知道帧格式后即插即用） | ✅ 读 `%APPDATA%\MouseDock\vendor-bt.json` |
| 接入设备面板 | ✅ HFP 读不到时自动尝试厂商通道 |

## 探测模式

```powershell
.\MouseDock.exe --vendorbt "Air Plus"
```

输出示例：

```
已连接厂商服务
被动 2 秒：无数据
  > 01    < 01 06 03 2A ...
  > 02 01    < ...
```

如果每一行都是「无数据」，说明这台设备要么不认这些通用帧，要么要求先做一次握手（正是 App 才知道的那部分）。

## 配置格式

知道协议后，在 `%APPDATA%\MouseDock\vendor-bt.json` 写：

```json
{
  "Air Plus Pro3": {
    "name": "vendor-v1",
    "requestHex": "01 05 00",
    "responseOffset": 3,
    "scale": 1
  }
}
```

| 字段 | 含义 |
|---|---|
| `requestHex` | 发给耳机的查询帧（十六进制，空格分隔；ASCII 可直接写文字） |
| `responseOffset` | 响应里第几个字节是电量（从 0 开始） |
| `scale` | `1` = 原始值就是 0–100；`3` = 0–3 档位；`9` = 0–9 档位 |

配置好后重启 MouseDock，面板就会显示百分比；读不到时仍然显示 `—`。

## 怎么拿到帧格式（唯一可靠的办法）

1. 准备一台 **Android** 手机（iPhone 拿不到 HCI 日志）
2. 设置 → 关于手机 → 连点「版本号」7 次，打开开发者选项
3. 开发者选项 → 开启「**启用蓝牙 HCI 监听日志**」
4. 把日志缓冲改成「**详细**」或更大
5. 连上耳机，打开厂商 App，进到显示电量的那一页，停留 10 秒
6. 开发者选项 → 「**生成错误报告**」→ 等它完成 → 分享/保存
7. 把 zip 里的 `btsnoop_hci.log` 拿出来（路径通常是 `FS/data/misc/bluetooth/logs/`）

拿到这个文件后，里面会有 App 与耳机之间完整的 RFCOMM 收发帧，
按「服务 UUID → 请求帧 → 响应帧」过滤，就能定位到电量那一对帧，
填进上面的 json 即可，**不需要改代码**。

## 为什么不做自动暴力扫描

向未知设备批量写入任意帧有把设备写进异常状态的风险（本项目在 2.4G 接收器上真实踩过一次）。
因此这里只发送**极短、只读语义**的探测帧，并且不把任何猜测值显示成电量。
