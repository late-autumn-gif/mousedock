# MouseDock v1.1.1 设备支持审计（2026-11-06）

本轮完成8K分类修正、D盘官方来源复核和全部已收录条目的运行时策略检查。**没有完成全部设备的实机验证，也没有把目录收录等同于支持。** 本包包含此前适配和六种悬浮图标，版本保持1.1.1。

## 8K接收器结论

修复残留的集合多数派分类：通用8K接收器同时暴露鼠标、键盘、控制器接口时，保留原始产品名、归为待确认，不凭辅助键盘数量确认键盘或型号。明确鼠标/键盘名称及专用确认路径保持有效。回归覆盖两种/三种接口混合、已知V75X键盘、专用ZERO鼠标、单一类型集合。精确排除用户报告的HM Lab扩展坞切换键HID C019:0401，邻近PID不屏蔽。

这是代码和离线回归验证；用户反馈电脑上的原始8K硬件未在本轮连接，尚不能宣称所有接收器固件均已实测修复。接收器发现、外设在线、型号确认和有效电量仍分别记录。

## D盘证据范围

检查15个品牌目录下2378个相关文件，10个不超过1字节的空文件/占位文件不能提供协议证据；不据此判定整个驱动损坏。MZ头检查只是库存可读性，不证明完整PE有效或协议兼容。HyperX目录为空，但实际NGENUITY驱动在“飓风”目录；没有因重复空目录认定驱动缺失。

13个既有分析目标/官方来源文件的SHA-256全部匹配，包括ATK网页代码、迈从G7网页代码、Rainy75驱动、罗技GPW模型、Airoha库以及既有反编译目标。哈希一致只说明这次核对的是同一份来源文件，不证明外设支持。旧REA记录用于目标身份与既有静态证据，新增检查为本地静态源码/IL反编译复核；未运行官方驱动、固件、配对或升级程序。没有把旧逆向笔记中的猜测当成已确认字段。

## 飓风/飓风3专项

Cloud III Wireless与Cloud III S Wireless分别处理，不能因同为Airoha或固件文件同处一个目录就共用型号映射。NGENUITY.dll、Cloud3_2nd和Cloud3S目录是不同层次的线索；例如03F00ACE.rfw文件名本身不足以新增USB型号强认。

官方Airoha枚举确认0x1D为GET_BATTERY_INFO；这**没有证明**旧62字节帧回复[6]就是百分比。0x48为游戏/语音平衡设置，不是充电查询；旧0x02猜测不能证明无线在线；Cloud III旧66/89笔记也不能由Cloud3S库旁证。相关推测解码已返回未知，直接旧读取入口在策略关口退出、不访问设备。

保留Windows原始音频名称，完整匹配HyperX Cloud III / III S及可选Wireless的扬声器形式，避免把III Keyboard等后缀当目标型号。现有Windows Headphones/Headset分类仍适用。按用户选择，所有耳机功能范围仍是**名称、播放音量、可恢复的麦克风静音**；不新增电量，也不按共享USB编号给其他耳机命名为竹林鸟。

## 验证与使用

11463条离线协议/集成断言、45项设备管理检查、17项模拟耳机UI/控制检查、162项真实Windows异步管道检查通过。管道测试没有访问外设；模拟音频检查没有写系统音量/静音。测试保留两处既有可空引用警告，应用自包含发布成功，0警告0错误。以上不是目标硬件的电量、连接成功率或实际音频操作验证。

退出旧MouseDock后，解压新版程序包运行。反馈仍异常时，用新版生成设备报告，才能分辨接口、接收器、型号和电量各在哪一层失败；旧版错误命名不能作为新型号确认依据。报告内的D盘路径仅供本地复核，驱动二进制和个人诊断数据不进入源码提交。
