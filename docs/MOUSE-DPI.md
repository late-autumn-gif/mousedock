# 主面板 DPI 验证记录

主面板的鼠标行显示当前硬件 DPI。设备支持写入时，点击数值可选择已有档位或设备允许的 DPI。修改后需回读确认。读不到时显示 `DPI —`。

## 迈从 MHUB 4D

官方网页驱动的 `readPerformanceInfo` 用 `0002` 取得配置编号，`readDpiInfo` 用 `0003` 获取档位。其 `setDpiInfo` 使用 `0103`，按配置号、轴、轴模式、档位数、所选档和 6 个小端数值编码。[MCHOSE M HUB](https://www.mchose.store/pages/mchose-hub)

MouseDock 在同一物理实例上完成现有的型号确认后，核对输入和输出能力表都声明报告 `4D`，再执行 DPI 请求。查询及写入校验命令、报告长度、状态、序列和 XOR。写入前重读配置与档位表。改档回读要求配置号、档位数和各档数值均一致。安全模式和设备识别关闭时跳过。独立 X/Y 配置显示 X 轴读数，切档入口关闭。

## 罗技 HID++ 2.0

| 型号 | DPI 路由及验证 |
| --- | --- |
| G Pro Wireless 初代 | `046D:C088` 有线和 `046D:C539` 接收器，离线通过。 |
| G PRO X SUPERLIGHT（GPW2） | `046D:C547` 接收器，离线通过。 |
| G603 | `046D:C539` 接收器，按实时型号识别，离线通过。 |

复用长报文的物理实例、配对槽位和型号检查。通过 HID++ Root 查找 `0x2201`，确认设备声明一个传感器，再读取传感器 0 的当前 DPI。设备处于主机模式，或明确未提供 `0x8100` 时，从 `0x2201` 的离散值或步进范围生成主面板候选项。写入前重查模式和可用值，写入后用新事务回读。板载模式、模式未知或能力不明时提供已确认的当前读数，关闭写入。应用不切换工作模式，也不写板载配置存储区。[Logitech DPI 功能规范](https://lekensteyn.nl/files/logitech/x2201_adjustabledpi.html) · [libratbag HID++ 实现](https://github.com/libratbag/libratbag/blob/master/src/hidpp20.c)

本机没有这些型号，三款均待实机。离线用例覆盖读数、改值、回读、错误软件 ID、型号变化、异常 DPI 列表及板载模式。其它 Logitech 通用接收器仍需单独验证身份和能力。

## ATK ZERO BITMOUSE

官方 ATK HUB 为 ZERO 使用报告 `08`。`0x09` 读取当前配置，`0x17` 分七段读取 DPI 档位，`0x02` 激活已有档位。MouseDock 校验应答的状态、命令、长度和分段地址。修改前重读配置和档位表，保留原有 X/Y 数值与档位颜色，随后回读配置和整张表确认切换。X/Y 数值不同或颜色包含额外数据时，只显示 X 轴读数。安全模式跳过厂商查询。[ATK V HUB 指南](https://www.atk.store/blogs/news/atk-v-hub-instructions) · [atkctl BITMOUSE 协议记录](https://github.com/cobanov/atkctl/blob/main/docs/PROTOCOL.md)

| 连接 | DPI 路由及验证 |
| --- | --- |
| 有线 `373B:1154` | 精确匹配 `ATK ZERO` 产品名。 |
| 2.4G `373B:1155`、`373B:124F` | 限定同一接收器实例，写入前后核对实时配对型号。 |

三个路由通过合成报文的读档、切档和回读测试，共新增 23 项断言。用例包含身份变化、错址、异常报文、无应答和改档回读不符。公开协议记录的硬件样本来自 A9 Plus NK。当前没有 ATK ZERO 的 DPI 实机回包，有线与 2.4G 均待实机验证。

## Scyrox V12M 2.4G

优先适配近期的 V12 系列。当前仅对已有电量支持的 `395A:0006` 接收器启用 DPI，限定同一实例内唯一的 `FF00/0002` 集合和双向 64 字节报告 `08`。S-Center 2.0 用 `0x2E` 读取在线状态与配对 VID/PID，`0x01` 返回配置流，`0x0A` 提交当前档位和已有数值。MouseDock 要求接收器返回在线的 `395A:0005`，等待配置流结束，再选择当前配置的数据。只在能确认配对身份和档位表时启用切档。配对身份用于内存中的一致性检查，不写入报告。 [Scyrox 官方驱动下载](https://www.scyrox.cn/download) · [S-Center 2.0](https://gaming.scyrox.net/)

读取 `0x25` 的独立轴标志，有独立轴时用 `0x23` 的 X 轴数值并关闭切档。写入前重读表，按官方格式原样提交现有数值。收到应答后回读配对身份、配置、档位和数值。出站帧使用官方加和校验，入站核对报告号、长度、命令及错误标志，切档结果由回读确认。安全模式和诊断回放不执行 DPI 事务。

协议依据为 S-Center 2.0 的 `index-CGLY9Ain.js`、`index-Dc7rvk5H.js`、`next-kzItA4cS.js`、`user-BnH2o-f-.js`。离线用例使用合成报文，覆盖多配置、配对更换、未终止的配置流、改档失败和主面板显示。待实机核对完整配置流和切档。有线及其他 V12 接收器仍待核对 HID 描述符。

本轮新增 24 项离线断言，总计 16,705 项通过。主面板 DPI 控件检查通过。用于核对配对状态解析的 `index-Dc7rvk5H.js` SHA-256 为 `449DAEC84D4CB3E4841C180E75F80A7F48534C670E5D4E0A5D21FBEB89B9990D`，用于核对配置流及写入格式的 `next-kzItA4cS.js` SHA-256 为 `78CF0D1BA04E1F86095B749DC4168755186F11523DFC7045B3B4F099B7BD4F20`。
