# 1.0.2 六款已验证设备的电量移植

当前项目版本仍为 **v1.1.1**。参考程序是另一作者的 MouseDock 1.0.2，不是本项目旧版本。

本次将其设备数据库中明确 `verified=true` 的六款设备的识别、电量读取、已知充电字段和可选型号身份查询移植进实际扫描流程。不是只加入六个显示名称，也不是把整个第三方数据库都标成已适配。

以上均为参考程序对应的无线接收器配置，不将其有线、蓝牙、8K 或相邻 PID 的其他版本自动视作同一协议。原项目已有历史实机记录的四组接收器继续保留：SC580 使用的 089D:062F、Neon75 Air 391D:2A05、MCHOSE A7 V2 Ultra+ 3837:100B、MCHOSE A7 5253:1021。

“精确描述符配置”说明名称来自 VID/PID 与私有集合组合，不等于接收器后的外设此刻已在线。当前外设状态与有效电量另有独立字段；F1 V3 若取得未知 CID/MID，则显示未知型号及身份值，不继续显示静态 F1 V3 名称。

## 移植的协议约束

- COMPX：17 字节，报告号/命令 `08/04`，拒绝错误状态 `FF`、校验和不为 `55` 和请求回显；有效电量为 0–100，包括 0%。
- Scyrox：64 字节，验证 `08/01`、在线/配置条件、配置索引一致性及 DPI 档位范围，再读取 `[20]`。不从其他字节推断充电状态。
- Sora：只走 Feature，不把 Input/Output 或相邻 AE8C 的另一种协议当兜底；`[12]==0` 时返回休眠/离线，不采用 `[9]` 电量。
- Rapoo：只接收原协议支持的 7/19/20 字节状态布局；休眠状态不成为百分比。不调用 VT2 MAX、VT7 或另一代 Rapoo 的主动查询帧。
- ATK F1 V3：电量有效后可发只读 `0x10` 身份查询；身份超时不丢弃有效电量。CID/MID 名称表只用于此精确配置的已校验应答，不扩大设备候选范围。

另外保留两项更严格的事务约束：旧输入队列在 32 次短读后仍未清空时不再发送查询；身份报文声明的载荷长度必须能装进实际 17 字节报文。这些不会把被原程序拒绝的数据变成电量或身份。

## 实例、安全模式与超时

读取器按物理 USB 实例选择一个满足精确集合和长度的通道；打开后再次核对 VID/PID 与能力。两台同型号设备不会共用电量或身份缓存。辅助键盘集合、错误用法、相邻 PID、报告长度不符、安全模式、已停用实例均不会进入该查询。

原生操作在拥有句柄和缓冲区的独立后台工作线程中执行。调用方超时后不会提前释放仍被驱动使用的资源，也不会在下一轮把迟到结果当新读数；同一路径未完成时不重复启动，最多四个挂起查询。后续系统缓存回退仍明确标注为旧值。
