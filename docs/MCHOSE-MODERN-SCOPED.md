## 来源与校验

官方网页驱动main-DCRwBIvm.js，SHA256：`405102805e2adeb93073ee2186f6d0193ca1317a6b4657d636e4e611bd25a446`。本轮从D盘已有官方资源静态复核mouseDiffConfig、readDeviceInfo、getCommandBuffer、mcReadCommand和deviceInfoToObj；未执行驱动、配对、升级或设置命令。原协议记录见[MCHOSE-A7-V3.md](MCHOSE-A7-V3.md)，本轮有限配置的机器可读数据见[MCHOSE-MODERN-PROFILES.json](MCHOSE-MODERN-PROFILES.json)。字节结构和型号表来自官方来源；测试回包是合成数据，不冒充真实捕获。

仅接受VID3837、完整原始名称和该型号的有线/接收器PID。仅选择本物理实例唯一FF01/0001、输入/输出/Feature=64/64/64集合，排除FF0B/00C4的61字节辅助通道；打开后再次复核设备属性和报告能力，能力表非空时必须取得唯一报告ID4D。其他固件布局未自动推测。

K5 Ultra 还允许相同 64 字节输入／输出集合没有 Feature 报告。该型号的输入和输出能力表必须都声明 4D，可以并存其他编号；若缺少 4D，则记录实际编号并跳过查询。

只发送4D/0900设备信息查询，保持官方默认flags1、biz0、sequence0，不假设固件支持自定义nonce。每轮排空输入并发送新查询，两次响应才采用第二次值；总预算与原生句柄归属沿用已有受限I/O机制。

响应严格64字节、头4D01、flags1、命令0009、biz/sequence0、载荷14至55字节且XOR正确。载荷[0..3]必须为3837与这个型号对应的本体PID；只返回1014/1018等接收器编号不确认外设型号。百分比取载荷[12]，范围0至100，0也有效；充电仅接受官方已知0/1状态。拒绝回显、错型号、错命令、越界、短包、坏校验和缺少第二次响应。

connectStatus枚举尚未完整确认，因此**不把两次接收器电量回复等同于RF外设在线**，PeripheralConfirmed保持false；读数表示本轮查询得到且符合协议的设备信息，无法据此证明所有休眠/离线固件行为。原始产品名与已确认型号分开保存，型号只在身份回包匹配后确认。
