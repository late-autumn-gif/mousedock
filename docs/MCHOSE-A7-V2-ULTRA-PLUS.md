# MCHOSE A7 V2 Ultra+ 电量适配记录

更新日期：2026-11-04。已在本机 `3837:100B` 接收器连接的 A7 V2 Ultra+ 上读到原始电量 85%、未充电，并验证发现服务、已保存的设备选择、电量模型及电量环显示链路。尚未实测插线充电状态切换、低电量和完整休眠/重连过程。

## 原因与适配范围

原有发现流程没有将 `3837:100B` 交给 MCHOSE 电量读取器；该设备使用 Legacy Feature 协议，不能套用 A7 V3 的 `4D/0900` 查询。

本次仅向同时满足以下条件的接口发送官方只读设备信息查询：

- VID/PID 为 `3837:100B`，产品字符串为 `MCHOSE A7 V2 Ultra+`。
- Usage Page / Usage 为 `FF01/0001`。
- 输入、输出和 Feature 描述符最大长度均为 65 字节。

共享接收器编号不能单独证明鼠标型号。其它型号、其它接口、有线通道和 IN9 Pro 不在本次适配范围。安全模式仍然禁止厂商查询。

## 官方协议依据

官方业务资源为 `https://www.mchose.com.cn/assets/main-B_prkphY.js`，SHA-256：

```text
233287E93E4EFE5AABF72053AE07B648A5068178BEB1E6C00AA01E654779530C
```

可按以下符号定位实现：

- `mouseDeviceReadOrder`：报告 ID `11`，设备信息命令 `06`，后跟 19 字节零。
- `readCommandEntrance`：命令与载荷按字节 XOR `FF`，使用 Feature 报告收发。
- `mouseDeviceReadParser`：小端 VID、PID、固件版本、连接位域、电量及充电字段。
- 型号表 `MCHOSE A7 V2 Ultra+`：本体型号 `4021`，接收器包含 `100B`。

包含报告 ID 的请求为 21 字节，即 `11 F9` 加 19 个 `FF`。集合的 65 字节描述符长度是不同报告的最大值，不是报告 `11` 的实际长度。

应答也按 21 字节解析：前两字节必须为 `11 F9`，其余 19 字节 XOR `FF` 后得到以下载荷：

| 载荷偏移 | 字段 | 本次校验 |
| --- | --- | --- |
| 0–1 | VID，小端 | `3837` |
| 2–3 | 本体 PID，小端 | `4021` |
| 4–7 | 固件版本 | 不用于推断电量 |
| 8 | 连接位域 | 低三位模式为 1，bit 3 在线；高四位保留 |
| 9 | 原始电量 | 0–100，保持原始整数 |
| 10 | 充电状态 | 仅接受 0/1，1 表示充电 |

空回复、请求回显、错误身份、离线状态、未知充电值及超范围电量均不产生有效读数。查询暂时失败时沿用现有缓存与过期标记机制，不能把未知解释为 0%。

## 为什么官方显示 90%，MouseDock 读取 85%

上述业务资源的界面格式化逻辑在 `batteryPrecision` 为 1 时直接显示原始值；传统协议使用 10 档显示，调用 `getRange` 和 `BATTERY_RANGE_TO_LEVEL` 转换。

区间表来自官方 `https://www.mchose.com.cn/assets/index-CcT60bJS.js`，SHA-256：

```text
35D414BA8B510842E8204B102F7972720AE8C3A112544A937CD68B8DCB7F356D
```

该表明确将 `75–84` 映射为 80、`85–94` 映射为 90、`95–100` 映射为 100。因此本机原始读数 85 与用户观察到的官方显示 90 相符。MouseDock 延续项目保留原始整数电量的规则，不将原始 85 改写成 90。

## 验证与限制

- 新增合成协议夹具，验证身份、接口、长度、连接状态、原始电量边界、充电标志及错误应答；不将个人硬件抓包提交到仓库。
- 实机连续十次生产读取中八次返回 85，两次未取得有效应答；后续发现快照及完整电量环链路取得 85，状态为已连接、未过期、已选中、未充电。
- 官方资源确认了字段和显示规则，但本次没有覆盖所有电量区间或实际充电状态切换。充电标志的离线测试不等于充电实机验证。
