# VT3 MAX：官方只读连接流程与持续监听（2026-11-15）

状态：已实现、离线验证；待目标接收器实机验证。不是整个 A HUB 设置/升级功能的移植，也没有证明解决用户实机问题。

## 证据与范围

用户确认官方 A HUB 可以显示电量。此前实机报告 `24AE:1417`、revision `0105` 的报告 07 接口打开成功，但三轮短时监听无输入。当前协议来源为官方网页 [A HUB](https://hub.rapoo.cn/) 的 `index-exv-sdE5.js`，SHA256 `F8E9B18C69EB294730FBBD6789FB04C542D1E5CEC6A0414F4067A173CD327984`。通过普通本地静态检查核对 Kk、qx、Gx、Vk、SC 和 S6，没有运行 REA 引擎，也没有抓取用户安装的桌面版 A HUB 通信。网页实现与桌面版是否完全相同尚未证明。

官方 Kk 建立输入事件处理后，在 onConnected 中获取配置列表/当前配置和当前 DPI；健康检查可读取四组鼠标/接收器固件版本。SC 使用报告 06 输出、Feature 08 应答。Kk.handleReport 对报告 07 解析电量。八个配置槽与其名称地址来自官方 O9/Z1/l1 表。

对应用户实机描述符：

| 通道 | 集合 | 布局 |
|---|---|---|
| 电量通知 | FF00/0002，MI_01/COL_09 | IN/OUT 07，19 字节 |
| 官方控制请求 | FF00/000E，MI_01/COL_05 | IN/OUT 06，33 字节 |
| 官方控制应答 | FF00/000F，MI_01/COL_06 | FEATURE 08，33 字节 |

官方 manifest 将 usage14 标为 `Only update Firmware`，但已检查的普通配置/DPI读取代码也指定报告 06；实机描述符把该报告映射在 usage14。因此本轮允许在该集合发送逐字节白名单内的官方只读请求，不能把这一许可扩大为升级、配对或任意写命令。此前文档“不访问该集合”的限制是旧实验方案，不再描述本轮实现。

## 实现

`RapooAhubProtocol` 承载独立纯协议逻辑。只允许 33 字节精确请求：8 个配置名、当前配置索引、所选配置名、默认配置的当前 DPI 档位及四组固件版本，共 15 次初始化事务。连接前缀为官方无线 A5；内存读取命令 A4，不是旧 A5 AA 电量协议，也不允许 A5 内存写入、AD 出厂恢复或其他命令。白名单覆盖请求的所有填充字节。

`RapooAhubSessions` 按物理实例建立一个后台工作线程及三个经重新校验的原生接口。先打开电量集合、清理旧队列，再执行只读初始化，初始化期间不再次丢弃新通知。应答必须有 Feature08 标识、成功 ACK；内存应答还验证命令、读取长度及状态。busy 按官方延时重试，最多五次；初始化预算 12 秒。失败记录最后请求、拒绝应答的脱敏头部及可取得的 Win32 错误，并保留未知。

初始化成功后，以有界 ReadFile 持续接收报告 07。按官方的单份通知模型采用完整、合法且 RF 在线的新帧；旧双通知和标准 GetInputReport 补偿不再用于当前生产路由，仅保留旧实现/回放兼容。最新通知覆盖此前事件，离线/无效帧清除待消费值。事件保留用户态读取时间，最多保留一个、最多 30 秒且只消费一次。每次刷新最多等待 4.5 秒，没有新事件不把已消费读数重新标为实时；已有界面读数的过期策略沿用电量服务。

扩展约束：最多四个物理实例会话；每实例 HidIoLease 排他；通道路径改变、拔出、安全模式、禁用识别或应用退出时请求停止；180 秒无刷新自动退出；失败后 30 秒退避。同步原生 Feature 调用无法强制取消，卡住时由原工作线程继续持有资源，不重复打开同实例；最多四个此类会话。超出初始化预算才返回的原生应答会被丢弃。后台线程/原生清理的实际驱动行为仍须硬件验证。

不复制官方 getAllConfigs 可能触发的默认配置创建，不执行配置/DPI设置、配对、复位、固件检查联网或升级。目标仅为既有无线 `24AE:1417/0105`，不扩大到未知有线 PID、固件版本或其他鼠标。

## 诊断与验证

报告保存 15 次白名单请求、脱敏应答头、必要的索引/档位字段、初始化完成标记及电量事件。配置名称、其他设置字段不保存。保留原采样时间，不能将持续会话中的旧初始化重新标成当前采集。回放同时校验三个精确集合、命令顺序、应答头、初始化/电量完成标记、最终成功状态及事件时间；旧 ZIP 无帧仍未知。

实际命令：

```powershell
dotnet run --no-restore --project tests/MouseDock.ProtocolTests -c Release -- --verify-rapoo-ahub
dotnet run --no-build --no-restore --project tests/MouseDock.ProtocolTests -c Release
dotnet publish src/MouseDock -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -p:DebugType=None -p:DebugSymbols=false -o <本地隔离测试目录>
```

AHUB 专项 610 项、全量 27320 条离线协议/集成断言、旧偏好 10 项、K87 13 项通过；测试项目保留既有编译警告。测试覆盖完整 15 次初始化、所有请求逐字节突变、错误应答/索引、单事件消费/过期/离线清除，以及逐帧删除、错实例/集合/命令/时间的回放拒绝。协议断言没有执行硬件 I/O，不等同于原生会话生命周期已实机通过。

自包含本地发布成功。打包程序 `--replay-report` 回放原用户 ZIP 退出码 0，三轮均 Failed/unavailable；使用明确标记的模拟完整事务也退出码 0，得到预设的 62%、未充电。该模拟结果仅验证打包后的解析，不是实际电池数据。离线报告和模拟样本保留于仓库外研究目录。

尚未验证：实际设备是否接受这些控制请求、各固件的应答头及通知触发时序、桌面版与网页驱动差异、休眠重连和与官方软件的争用、长时间 CPU/句柄占用。没有执行全量 GUI 或实机性能测试。下一步使用完整解压的本地隔离测试包，退出旧实例和官方 A HUB，唤醒鼠标后刷新，导出当前雷柏报告；逐阶段核对初始化及报告 07 事件，再与官方电量对照。
